# 常见报错与排查

[返回首页](../../README.md) · [配置与烧录](getting-started.md)

以下案例来自本次实战派适配。相同表面现象可能有不同原因，先核对串口日志、板型与实际画面。

## 屏幕完全不亮，或亮度调整方向反了

本板 GPIO42 背光为低有效。当前板级驱动已使用反相 PWM。先核对构建确实使用 `sdkconfig.muse-lichuang-szp`，再检查亮度和背光；不要套用同芯片其他开发板的 GPIO 表。

## 程序截图有画面，实体屏幕仍是空白

本次故障出在 LCD 初始化与片选时序。当前驱动先在 PCA9557 控制的 LCD_CS 为高时建立 SPI mode 2 的初始时钟状态，再选中屏幕、复位，并在退出睡眠前留足复位等待时间。

检查实体屏幕是否有背光、日志是否识别实战派、是否误用了其他板型或旧构建。若继续排查，可临时做纯色测试来区分 UI 绘制和屏幕传输，但正式版不保留这些调试入口。

代码入口：[`board_lichuang_szp.c`](../../esp32/components/muse/boards/board_lichuang_szp.c)。

## 手机能发现设备，但提交 Wi-Fi 后断开或出现 error_operation_in_progress

历史问题是扫描后仅剩约 6 KiB 连续内部内存，而配网任务需要 8 KiB 栈空间，任务没有成功启动。当前驱动把双刷新缓冲区从各 32 行缩为各 8 行，释放 30 KiB 内部内存；预设也包含对应的 PSRAM 和网络内存设置。

这条错误信息本身不能证明一定是内存不足。请同时检查任务创建失败和堆内存日志，确认是否使用了当前驱动及预设。只更改密码或重做配对不能解决任务分配失败。

## 输入框跑到屏幕外，键盘挤满页面

曾经的输入页按更高屏幕布局，放到 240 像素高的横屏后越界。当前适配使用顶部标题和输入框、底部四行键盘。

确认已构建本适配版本的 [`muse_settings_ui.c`](../../esp32/components/muse/muse_settings_ui.c)，而非只拷贝板型文件到原始上游代码。UI 修复、翻译模块和板型配置应一起使用。

## 中文显示异常，或重启后语言与默认值不同

确认实战派预设启用了 `CONFIG_MUSE_CJK_FONT=y`，并包含 [`muse_ui.c`](../../esp32/components/muse/muse_ui.c) 中的字体回退处理。旧构建的 `sdkconfig` 可能覆盖后来修改的预设，重新生成干净的板型构建配置后再检查。

保存过的语言优先于首次默认值：修改 `MUSE_DEFAULT_CHINESE` 不会覆盖设备中已经保存的英文选择。直接在设置中切换即可，无需清空配对。

## Wi-Fi 已连上，但出现 CAN'T REACH MUSE 或 API 超时

分别核实三个阶段：

1. 蓝牙配对是否完成、凭据是否保存。
2. Wi-Fi 是否连接、是否获取 IP。
3. 开发板实际使用的网关和网络能否访问 Muse 服务。

本次记录中电脑通过本机代理能收到 HTTP 响应，但绕过代理走路由器同样超时。开发板没有自动继承电脑的代理路径。手机 App 可用、电脑浏览器可用，都不能单独证明开发板能访问同一服务。

在开发板实际使用的网络路径上检查 DNS、连接和超时日志。手机热点也不能默认认为会共享手机的 VPN。当前端到端在线对话仍未验证；不要用反复烧录或清空配对代替网络诊断。

## 编译失败、缺少头文件或修改预设后没有生效

先确认 `idf.py --version` 为本仓库使用的 v6.0.1，再确认源码和构建目录采用英文、无空格路径。缺失的 `gcm.h`、`gpio_ll.h` 等可能与 ESP-IDF 版本不符有关，应结合具体编译输出判断。

生成的构建配置优先于预设：移走旧构建目录，再按快速开始重新配置自己的 token。不同板型切换时，共用的 `managed_components/` 和 `dependencies.lock` 也可能造成依赖冲突；停止其他构建，按[上游构建说明](../../esp32/AGENTS.md)处理生成依赖后重试。

## 反馈问题时提供什么

请提供板卡准确型号/版本、Flash 与 PSRAM 容量、源码提交号、ESP-IDF 版本、所用板型、复现步骤，以及相关错误附近的日志。说明是内部截图异常还是实体屏幕异常，能提供现场图片更容易判断。

提交前移除 SDK token、Wi-Fi 密码、配对信息和私人网络标识。不要上传整片 Flash 备份或个人构建固件。
